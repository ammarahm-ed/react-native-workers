Post 2 the API
If you've used a Web Worker, there is nothing new to learn. A worker is a normal module that happens to run on its own thread. postMessage in, onmessage out, terminate() when you're done. That's the whole API surface.

Card: code — the two-file hello world.

The Worker API you already know

App.js
const worker = new Worker('./workers/heavy');
worker.onmessage = (e) => console.log(e.data);
worker.postMessage({ items: 100_000 }); // returns instantly

// workers/heavy.js — its own thread, its own runtime
self.onmessage = (e) => self.postMessage(expensiveWork(e.data));

Post 3 not worklets
"Is this Worklets under the hood?" No — and that's the point. Each worker is a separate Hermes runtime on its own OS thread: own event loop, own bundle, full import support. A Metro transformer bundles each worker file for you. Worklets share a runtime. These don't.

Nothing is shared implicitly. Messages cross via structured clone; each worker gets its own CallInvoker, so async native work resolves on the worker's own thread.

Post 4 expo modules
A thread that can only do math is useful. One that reaches the native side is a different tool. C++/JSI modules work in every worker. Your app's Java/ObjC TurboModules are a flag away. And Expo Modules run inside a worker — iOS and Android. Constants, sync + async fns, events.

Card: code — requireNativeModule inside a worker.

Expo Modules, inside a worker

workers/probe.js
const Device = requireNativeModule('ExpoDevice');
Device.osName;                        // constants
await Device.getDeviceTypeAsync();      // async fns

const Crypto = requireNativeModule('ExpoCrypto');
Crypto.randomUUID();                  // sync — a value, not a Promise
Foo.addListener('onX', handle);      // module events, in the worker

iOS forwards each call natively through Expo's AppContext. Android builds a genuine per-worker AppContext. Same code either way.

Post 8 experimental · Thread
The newest piece moves the thread, not the data. Thread (experimental) lets a worker's runtime run somewhere else for a moment — the main thread, or one you create. No second runtime. Nothing serialized. Just a closure keeping everything it captured — only the thread changes.

Card: code — thread hopping.

Move the thread, not the data

workers/video.js
enableMultiThreadingExperimental();
const codec = Thread.create('codec');

await codec.run(() => {
  const pixels = decodeFrame(bytes);   // on the 'codec' thread
  Thread.main.run(() => paint(pixels)); // on the main thread
});

Same variables, same objects, same identity. It's thread affinity, not parallelism — one thread is ever inside the runtime.
